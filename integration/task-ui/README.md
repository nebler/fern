# Fern Task UI Fixture Renderer

An isolated, read-only fixture renderer built from the task contract. It is not
the production phone page in `internal/proxy/task_ui.go`, which supports durable
submission retry, cancellation, sealing, and server-backed status polling.

## Preview

From the repository root:

```sh
go run ./integration/task-ui -addr 127.0.0.1:8787
```

Open `http://127.0.0.1:8787`. The server performs no external calls and exposes
only GET/HEAD preview routes.

## Tests

```sh
go test ./integration/task-ui
```

Tests cover fixture validation, documented task/publication state vocabulary,
required state examples, inbox/detail rendering, exact OpenCode deep links,
HTML escaping, read-only method handling, and response security headers.

## Integration Contract

The renderer expects a workspace task snapshot equivalent to:

- `TaskSummary`: ID, title, task state, numeric repository ID and display name,
  base SHA, current attempt ID, pending approval count, result ID, current
  publication summary, revision, timestamps, and `self`/`opencode` links.
- Task detail: attempt summaries, current approval summaries, cancellation
  facts, immutable result summary and changed-file metadata, verification
  summaries, current publication summary, and latest Fern event cursor.
- Links: `links.opencode` must be an exact same-origin `/session/{sessionId}`
  deep link. The host integration is responsible for routing that path to the
  official OpenCode UI.
- Publication pull request URLs are display-only links supplied by the trusted
  Fern API projection.
- All timestamps are UTC RFC 3339 values; Git/object and Fern/OpenCode IDs stay
  opaque and are never generated by the UI.

This fixture UI does not infer terminal state from connectivity or event absence.
It does not implement submit, cancel, approval, verification, publication,
retry, or recovery APIs. It deliberately does not reproduce OpenCode transcripts,
tools, permissions, questions, forms, terminals, files, or diffs.

`fixtures/tasks.json` includes required task-state examples and representative
publication stages. The state allowlists in `model.go` contain only the exact
documented vocabulary and reject fixture drift.
