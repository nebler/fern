**Date:** 2026-08-23
**Scope:** Fresh codebase inventory of fern at `f8fc396`, plus new online research across
opencode (v1/v2), Amp and the agent-harness competitive field, the agent-sandbox

## TL;DR

1. **The repo is far ahead of the strategy docs — but it diverged from all three plans.**
   fern is no longer a pause/wake wrapper. It is a *durable task system*: SQLite journal,
   exact-once delivery, cancellation fences, user-authorized result sealing, hardened
   verification runners, GitHub App publication coordinator, phone pairing, mobile task UI.
   Meanwhile all three headline recommendations from the prior documents — pre-warmed pool,
   LLM gateway, `/remote` migration — remain **unbuilt**, and one core assumption was wrong:
   **fern's "pause" is `docker stop`, not the freezer cgroup** (`internal/runtime/docker.go`
   calls `ContainerStop`). The 2.8–3.1 s wake is a full container restart. The single
   highest-ROI item from every prior report is still on the table.
2. **The target Grab role now exists and is better than expected.** A live posting:
   **Senior Software Engineer, Backend (AI) — Petaling Jaya, Malaysia (onsite)** on the
   Applied AI team owning the GrabGPT Gateway. It is in Malaysia (no Employment Pass
   needed), and the JD *verbatim-confirms* items previously flagged unconfirmed:
   Redis-backed distributed rate limiting, SSE streaming with automatic fallback, Go+Python
   low-latency reverse proxy, token-level metering → PostgreSQL/data-lake chargeback,
   OIDC/workload identity, LangChain/LangGraph familiarity.
3. **Google validated fern's architecture.** In May 2026 Google shipped **agent-substrate**
   (with Solo.io; CNCF-endorsed): an actor/worker control plane that multiplexes idle agents
   onto warm workers with sub-second suspend/resume and deliberately bypasses the Kubernetes
   API in the hot path. That is fern's idle-stop + wake-on-request design at hyperscaler
   scale. GKE Agent Sandbox also hit GA (May 20, 2026, free add-on). The "do not build a
   K8s control plane" verdict is now triple-confirmed.
4. **opencode moved toward fern's root blocker.** v2 public beta (~July 23, 2026) persists
   every session event with `(version, seq)` in SQLite/WAL and exposes cursor-replayable
   event/history endpoints (`GET /api/experimental/session/{id}/log?after=`,
   `GET .../history`) plus idempotent prompt-admission receipts. `/wait` is still stubbed
   and SSE still has no Last-Event-ID replay, but a polling-based terminal-success observer
   — fern's missing piece — is now realistically buildable against the pinned profile.
5. **Recommended sequence (weekends):**
   ① freezer-pause conversion + wake-trace waterfall →
   ② terminal-success observer on v2 durable events (closes seal → verify → publish
   end-to-end automatically) →
   ③ fern AI Gateway aimed clause-by-clause at the PJ JD →
   ④ notifications (ntfy/webhook) + a tiny LangGraph consumer →
   ⑤ self-hosted wake-latency benchmark essay →
   ⑥ one upstream opencode PR (Bearer auth #24874 or durable-event replay #38458).
   Do not build: Kubernetes controllers, microVM re-platforms, bidirectional live session
   migration, or a company.

## Part 1 — What fern actually is today (repo reality)

Inventory at commit `f8fc396` (module `github.com/nebler/fern`, composition root
`cmd/fern/up.go` + `cmd/fern/tasks.go`). Code and tests are authoritative per
`docs/ARCHITECTURE.md`.

### 1.1 Lifecycle: the pause assumption is wrong

| Claim | Reality |
| --- | --- |
| "Pause" mechanism | `Docker.Pause` → `pauseObserved` → `cli.ContainerStop(..., Timeout: 10s)` (`internal/runtime/docker.go:281–352`). Domain vocabulary only; **no freezer cgroup use** |
| Freezer handling | Defensive only: if a container is found frozen, fern calls `ContainerUnpause` before stop (`docker.go:337–341`), on resume (`460–463`), before destroy (`529–534`). Fern never calls `ContainerPause` |
| Stop-vs-crash disambiguation | Durable intent store (`internal/runtime/runtime.go:32–47`: `BeginPause/CommitPause/CommitShutdown/PauseStatus/Clear`); classification in `inspectByReference` (`docker.go:608–649`): exited+committed intent = paused; exited without intent = failed |
| Wake sequence | Request classified (`internal/proxy/proxy.go:259–276`: observe/read/work) → `Manager.AcquireRequest` admission lease → coalesced wake (90 s timeout) → `ContainerStart` + re-inspect + health poll (`/api/health`, 200 ms tick, 60 s budget, negative auth probes) → endpoint generation published → `httputil.ReverseProxy{FlushInterval:-1}` |
| Pre-warmed pool | **None anywhere** (grep confirms). Single workspace per process (`internal/workspace/manager.go:50`) |
| Latency instrumentation | Partially exists: wake >100 ms logs `wake_ms` (`proxy.go:222–224`); create/resume elapsed logged (`docker.go:277,488`); lifecycle harness times 10 real stopped→ready wakes into `wake-timings.tsv` (`integration/lifecycle/run.sh:22,532–550`) |

Implication: the freezer conversion is *small* because the state machine already
understands frozen containers defensively, and measurement already half-exists.

### 1.2 What is implemented (production-wired)

- Two loopback listeners with distinct policies: remote/device (Tailscale Serve target;
  pairing codes, digest-backed 30-day device grants, CSRF + Fetch-Metadata enforcement) and
  operator (Basic auth; never published).
- Request admission with intent classes; concurrent-wake coalescing; conservative two-pass
  idle barrier over six activity surfaces (`/api/session/active`, shell, PTY, permission,
  form, question).
- Durable task pipeline: idempotent admission (caller-chosen OpenCode session/message IDs,
  `Idempotency-Key` receipts), exact-once delivery with persisted phases
  (`claimed → session_create_started → session_ready → prompt_started`), cancellation
  fences, conservative execution observation (running / input_required only — never infers
  terminal success), explicit quiesced result fence (`AcquireQuiesced`), read-only Git
  result collector with bounded canonical manifests + SHA-256, user-authorized sealing
  (`seal-preview`/`seal` API routes exist), optional fenced verification runner
  (symlink-refusing openat executable resolution, process-group teardown, clean-commit
  proof before/after), GitHub App brokered publication (RS256 JWT → installation tokens,
  single-use askpass pushes, journal-fenced push/PR-create with read reconciliation).
- SQLite task store: WAL, FKs, trigger-enforced immutable state machines, migration
  checksum verification, CGO-free.
- GitHub authority modes: `github-app-broker` fully wired; `workspace-gh` wired for task
  base-resolution via token-free probes running pinned `gh` inside the attested container.
  The legacy host-credential publisher is implemented but **unwired** in this composition
  root (`cmd/fern/up.go:347–358` returns nil).
- Mobile: embedded task UI (`internal/proxy/task_ui.go`) with submit/list/cancel/seal +
  CSRF flow; QR pairing page; richer read-only prototype in `integration/task-ui/`.
- Release/deployment: reproducible release harness (dual-build compare, SHA256SUMS),
  fail-closed host backup/staged-restore/rollback script with epoch locks, hardened systemd
  unit, CI covering gofmt/tests/race/vet/build/lifecycle/OpenCode smoke/browser rehearsals.

### 1.3 What is missing or blocked

| Gap | Status |
| --- | --- |
| Generic terminal-success observer | Root blocker. No production implementation of `Observer.ObserveSucceeded`; attempts cannot become `succeeded` except by explicit user seal; verification/publication coordinators starve without sealed results (`docs/TASK_MODEL.md`, ARCHITECTURE gaps #4/#5) |
| Fast wake path | Unbuilt (see §1.1) |
| LLM/AI gateway | Zero code. Provider keys forwarded into container env (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY` eligible for forwarding; host-only names rejected) — the exact posture prior docs identify as the weakness |
| Rate limiting / routing / cost attribution | None |
| Notifications | None (no ntfy/webhook/push code) |
| Multi-workspace routing | None (single workspace) |
| MCP server, plugins, `.opencode/command/*` | None shipped |
| Durable approvals | No approvals table/API; permissions/forms are process-epoch scoped in the pinned profile |
| Physical acceptance | Real TLS/WSS, reboot/restore, ACL-negative tests outstanding |

## Part 2 — opencode state (August 2026)

Repo: `github.com/anomalyco/opencode` (moved from `sst`; default branch `dev`).
v1 stable line `opencode` (npm `opencode-ai`) at **v1.18.21** (2026-08-21); **v2 public
beta** since ~2026-07-23 as side-by-side binary `opencode2` (npm `@opencode-ai/cli@beta`),
explicitly unstable; no Homebrew/Docker/standalone distribution for v2 during beta.
Schema changelog: `specs/v2/schema-changelog.md` — experimental events/projections were
**reset wholesale on 2026-06-22**; interruption made process-local; `GET /api/session/:id/
history` added 2026-06-26. fern pins `0.0.0-next-17444` (digest-verified) — a v2 beta
build, consistent with the inbox/prompt-receipt surfaces fern already uses.

### 2.1 Durability surface (the root-blocker news)

Confirmed present in the v2 architecture:

- SQLite/WAL storage (`~/.local/share/opencode/opencode.db`); sessions/messages/parts/
  events persisted; externally inspectable.
- **Durable event log with sequence cursors**: every public session event carries
  `(version, seq)`; documented endpoints include
  `GET /api/experimental/session/{id}/log?after=&follow=true` (replay after exclusive
  cursor then tail) and finite paginated `GET /api/session/{id}/history`.
- **Idempotent durable prompt admission**: `POST /api/session/{id}/prompt` writes
  `session.next.prompt.admitted.1`; duplicate submissions return the same receipt.

Still missing/broken:

- `POST /api/session/{id}/wait` returns 503 ("not available yet") — stubbed everywhere
  including dev branch.
- `GET /api/event` is volatile by contract ("events during disconnection are missed"); no
  Last-Event-ID replay anywhere; on stable 1.18.x HTTP-created sessions cannot reach the
  durable layer (`sync/steal` → 400). All catalogued in open issue
  [#38458](https://github.com/anomalyco/opencode/issues/38458) (assigned, active Aug 10).
- Permissions/forms durability across restart: undocumented/unconfirmed; known bug signal
  that permission/question asks emit no SSE events (#38458 Issue 2).

**Consequence for fern:** a *polling* supervisor loop is viable today on the pinned
profile: admit prompt (receipt + messageID) → poll message/status (or read `opencode.db`
read-only) until a terminal assistant message → optionally cross-check the cursor log
endpoint. That is the first production `Observer.ObserveSucceeded`. Design it behind an
adapter so the eventual `wait`/replay primitives slot in.

### 3.2 Harness sweep — the three hunts

**(a) True bidirectional live-session migration local↔cloud:** still shipped by nobody.
Closest: GitHub Copilot's checkpoint-based pull/push (`/delegate` + pressing `&` in CLI;
creates checkpoint branch + draft PR rather than teleporting a live process; resume bugs
reported). Codex handoff is genuinely bidirectional but only between hosts you own, over

(cloud→terminal); `claude remote-control` matured (QR, server mode, ~4 h resume windows)

**(b) Wake-on-webhook/event as first-class:** now four flavors — Amp webhooks, Cursor

Routines. Table stakes; do not pitch as novel.

**(c) Notification-on-completion:** Slack-first nearly everywhere; native phone push only
Claude cloud routines. ntfy/Telegram remain a third-party plugin ecosystem (pygmy,
claude-notify-everywhere, agents-router — the latter watches opencode too). **fern
shipping ntfy/webhook natively would be ahead of every major harness except Slack-first
integrations.**

Other notables: Cursor Cloud Agents gained computer-use takeover, "Builds" warm snapshots,
cloud subagent swarms, iOS app; Codex announced (not yet shipped) TUI-as-client-of-remote-

MCP Aug 20; supports OpenCode), Nimbalyst active (supports OpenCode alpha), Vibe Kanban
community-maintained post-Bloop, amux active (Rust rewrite), Uzi stale.

**Positioning honesty check:** don't lead with "remote sandbox manager" (Amp/Cursor/Copilot
own hosted versions). Lead with: **self-hosted, provider-neutral (opencode), your Docker,
your Tailscale, your keys, exact-once semantics** — the quadrant nobody occupies, with Vibe
Kanban's death leaving the vacuum unclaimed.

## Part 4 — Agent-sandbox infrastructure market (August 2026)

### 4.1 The Kubernetes answer industrialized — and then went beyond K8s

- **GKE Agent Sandbox GA May 20, 2026** (free add-on `--enable-agent-sandbox`); Google
  claims 300 sandboxes/sec/cluster with 90% of allocations under 200 ms [V], warm pools
  backstopped by suspended-VM buffers, Pod-Snapshot suspend/resume; gVisor enforced via
  admission policy; adopters named: LangChain, Lovable [V]; Anthropic Managed Agents run on
  it in Google's reference samples. OSS `kubernetes-sigs/agent-sandbox`: weekly releases
  (v0.5.6 Aug 20; 3.6k★), v1beta1 CRDs (`Sandbox`, `SandboxTemplate/Claim/WarmPool`),
  suspend/resume latency histograms, Firecracker-via-Kata example (~125 ms boot [V]).
- **agent-substrate** (Google + Solo.io, May 20; CNCF blog Jul 7): an actor/worker control
  plane that multiplexes many idle actors onto few ready workers, sub-second
  suspend/resume via gVisor checkpoint/restore or microVM, actor snapshots to object
  storage, traffic routing included, and **explicitly bypasses the Kubernetes API in the
  hot path** because "millions of sub-second tool calls would overwhelm a standard control
  plane." CNCF framing: agent-sandbox = secure singleton workloads; agent-substrate =
  wake-on-invocation serverless-style density. **This is fern's architecture validated and
  productized at hyperscaler scale — cite it in interviews as prior art, not competition.**

Verdict unchanged, thrice-confirmed: solo devs should not build K8s control planes; the
frontier has already moved past them.

## Part 7 — Recommended roadmap

Reconciles the three prior documents (doc 1: gateway first; doc 2: `/remote` first;
doc 3: warm pool first) against repo reality and August intel. `/remote` is formally
dropped: upstream import bugs staled unfixed (#15797/#20117/#21941) and fern already

**Weekends 1–2 — Freezer pause + wake waterfall (P0).**
Convert idle-stop from `ContainerStop` to freezer pause behind `idle.mode: stop|freeze`.
Teach the classifier that frozen-with-intent = paused (defensive unpause paths already
exist). Keep the two-pass all-idle barrier identical. Document the honest cost: paused
containers hold full RSS. Add `fern wake --trace` (millisecond waterfall). Measure via the
existing lifecycle harness. Target: sub-100 ms wake, logged and graphed.

**Weekends 3–4 — Terminal-success observer on v2 durable events (P0.5).**
Prototype against the pinned build: admitted prompt receipt → poll message/status until
terminal assistant message (optionally cross-check

slot in). Effect: seal → verify → publish runs automatically end-to-end. Demo sentence:
"I text a task from my phone; it wakes in <100 ms, works, verifies itself, opens a draft
PR."

ntfy/webhook push on `input_required` and completion (small; ahead of every major

## Part 8 — Anti-recommendations (still firm)

1. **Kubernetes CRD/controller phase.** GKE Agent Sandbox is GA and free; agent-substrate
   commoditized the pattern upward. Building this now competes with hyperscalers and
   signals the wrong door. Exception stands only if an interview loop explicitly demands
   operator experience — timebox 2 weeks, separate repo.
2. **MicroVM/Firecracker re-platform.** Throws away the entire Docker investment for
   latency the freezer gives you for a config flag.
3. **Bidirectional live session migration.** Nobody ships it; upstream transfer paths are
   broken; fern's durable-task model is the better answer to the same need.
4. **Productization/company ambitions.** Terragon, Ona, Vibe Kanban, Daytona reinforce:
   portfolio artifact, not startup.

## Part 9 — Caveats

- **v2 churn is real**: schema changelog shows wholesale experimental-event resets
  (Jun 22) mid-development; fern pins digests and must keep re-verifying via
  `integration/opencode-contract` on every bump. Treat the durability endpoints as
  beta-stable, not stable.
- Permissions/forms restart durability remains unconfirmed on any build; fern's
  fail-closed posture stays correct.
- Stale-bot closures ≠ wontfix; conversely, closed-completed ≠ fixed-on-your-pin.
- Vendor latency/pricing claims are directional; prefer the LogRocket independent
  measurements and your own harness output.
- Job postings rotate quickly (a Singapore Merchant AI role already closed); confirm the
  live JD text at application time.
- This document is point-in-time research (2026-08-23). `docs/REMOTE_PRODUCT.md`,
  `docs/ARCHITECTURE.md`, and the code remain authoritative for direction and behavior.
