# fern R6: The Phone-Operated Agent Fleet — Five-Year Vision, the microVM Fork, and Where We Stand

**Date:** 2026-08-23
**Scope:** Visionary direction for fern under the constraint *opencode v2 only* (`anomalyco/opencode`,
v2 API/docs/client, beta), the microVM-vs-containers architectural fork, and an honest
assessment of the case against the whole project. Builds on R5 (same folder) rather than
repeating its landscape findings. Written for a weekends-only solo builder concurrently
preparing DSA/system-design interviews for the Grab Applied AI (GrabGPT Gateway) role in
Petaling Jaya.

---

## TL;DR

1. **The phone-fleet thesis is directionally right and institutionally backed — but it is a
   *triage* thesis, not a *steering* thesis.** The evidence supports phones becoming the
   primary surface for dispatch, interruption-driven decisions, and approval-shaped review
   by 2028–2031 (Anthropic's fleet framing + mobile approve flows, voice dispatch landing in
   both major CLIs, IETF "Progressive Trust" standards work, cost curves decoupling fleet
   size from budget). It does **not** support rich real-time steering or large-diff review
   from a phone: the measured review ceiling is ~50-line diffs, and METR/DORA data says
   review bandwidth — not generation capacity — is the binding constraint. Design for
   decisions, defer depth to the desk.
2. **microVMs: never-for-now.** Every serious microVM player is a multi-tenant,
   untrusted-code business; their constraint is not yours. Stay on Docker + freezer pause
   (the pivot that was recommended in R1–R3 and still isn't built). gVisor `runsc` is the
   designated first response if you ever run genuinely untrusted code; Podman CRIU is the
   designated response to a RAM wall; Firecracker only if fern becomes a real multi-tenant
   product — which the market analysis says it won't. Pivot-now cost: 10–16 weekends to
   reach worse-than-today functionality. Stay cost: ~one weekend (the conversion itself).
3. **fern's existing architecture is accidentally (now deliberately) the right shape for
   the 2028–31 world**: durable tasks with exact-once delivery, sealed results, and
   fail-closed observation treat opencode as a replaceable compute engine whose process can
   die anytime — precisely matching the supervising-*outcomes*-not-*conversations* shift
   the ecosystem is making (Claude dynamic workflows, runs-not-sessions).
4. **The Grab answer:** the phone-fleet vision alone reads as an adjacent platform project.
   The version that reads dead-on-target is the same system with the **LLM credential
   gateway as its load-bearing enforcement plane** (keys never enter the workspace;
   per-workspace tokens; Redis-style token buckets; token metering → cost rows; SSE
   passthrough). Trust budgets and spend caps *need* a model-boundary gateway to enforce —
   the two visions interlock. Build that one artifact; it serves both masters.
5. **Where we stand, bluntly:** the strategy has been stable across four documents and the
   top-ranked item (fast wake) is *still* unbuilt while the repo accumulated extraordinary
   invisible machinery. That is the documented over-design pattern operating in real time.
   The next eight weekends are already decided; execute them before believing any new plan,
   including this one.

## Part 1 — The vision essay: one engineer, a fleet, and a phone (2028–2031)

### 1.1 The argued position

By 2030, the scarce input in software production is not keystrokes and not even model
tokens — it is **judgment moments**: points where a human must decide something only a
human can decide (is this change safe to ship? which approach do we take? may this agent
touch production?). Everything about the intervening years points at supervision becoming
an *interrupt-driven triage activity*, and the phone is the only device humans carry that
is natively interrupt-shaped, always present, and optimized for quick decisions over deep
work.

The signals, compressed:

- **The largest vendor committed its UX roadmap to the metaphor.** Anthropic launched web +
  iOS Claude Code with explicit fleet language ("oversee a fleet of Claude Code
  instances… delegating to an entire team", Oct 20, 2025) and now ships Dispatch,
  Channels (Telegram/Discord/iMessage plugins), QR-paired Remote Control, and literal
  "Approve tool calls from your phone" flows.
- **Concurrency is scaling behind a script, not a UI.** Claude Code's dynamic workflows run
  up to 16 concurrent agents (1,000/run cap) with the *script* holding the plan; the human
  approves plans and verdicts. The unit of supervision is shifting from session → run/task.
  Practitioner consensus puts human-attended concurrency at 3–8 (Steinberger 3–8, Osmani
  4–5, Totalum's "3–5 is the sweet spot").
- **Economics decouple fleet size from money before they decouple it from attention.**
  Capability-adjusted inference prices fall ~9–900×/year (median ~50×, Epoch AI). By 2028,
  running 10–50 personal agents is rounding error; the constraint is judgment moments.
  That asymmetry *is* the thesis.
- **Voice landed inside the dispatch path.** Claude Code `/voice` (Mar 2026) works in the
  agent-view dispatch input; Codex adopted Wispr Flow; Aura demonstrates local-first
  voice→approve→dispatch loops. Speaking (~150 wpm) beats typing (~40 wpm) exactly when
  your output is instructions — i.e., on a phone, walking.
- **Trust formalization began.** An IETF internet-draft defines behavioral Progressive
  Trust Scores with decay and approved elevation; academic work targets ~85–90%
  auto-approval with escalation only at decision boundaries; Coder ships Agent Firewall
  (default-deny per-agent egress, audit logs). Survey data: 53% of orgs report agents
  exceeding intended permissions — governance is coming whether we like it or not.
- **Security incidents make the supervisor role *more* important, not less.** Nx
  "s1ngularity" showed malware invoking coding CLIs to hunt secrets (33% of victim systems
  had one installed); BeyondTrust/Unit 42 escaped AWS AgentCore via DNS tunneling and IAM
  god-mode. Per-agent identity, egress policy, and audit trails become mandatory — and a
  human approving only irreversible doors is the cheapest control there is.

### 1.2 What it concretely looks like (a day, 2029)

You run 6–14 workspaces across 3 machines in your tailnet. You never open a laptop before
noon unless you want to.

- **07:40, commute:** You speak three dispatches into your phone ("update the design-system
  dep across the four apps, one PR each, run the visual tests"; "investigate last night's
  flaky payment test, don't fix yet, report"). fern admits them durably — idempotency
  receipts, caller-chosen IDs — and wakes workspaces in tens of milliseconds from a paused
  pool. Your phone shows a fleet-glance card: 11 running / 3 queued / 0 blocked.
- **Day:** You work on whatever you choose. The phone is silent except for two Tier-1
  interruptions: an agent wants to force-push outside its sanctioned ref (inline Deny from
  the banner — 5 seconds), and one agent hit its spend cap mid-task (inline "raise cap /
  pause"). Everything else files silently into the review queue.
- **21:30, couch:** The evening digest ranks the day's output by *outcome quality*, not
  arrival order: two green-CI small diffs with passing sealed verifications get inline
  Approve; one "suspicious success" (agent claimed done, verification absent) gets
  escalated-to-desk; a 600-line refactor is flagged beyond phone budget and deferred with a
  prepared review bundle. Total triage time: 12 minutes. You approved ~70% of shipped
  lines without ever reading them — because the *verification lane*, not your eyes, cleared
  them, and your trust ledger says these agents have earned that on this class of change.
- **Saturday, desk:** One deep session. The deferred bundle opens straight into context:
  diff, agent transcript permalink, verification evidence, your half-written comments from
  Thursday. You finish the review once, at depth.

### 1.3 What must become true for this to work

1. **Review units shrink to phone size** — stacked small PRs, agent-authored summaries
   with evidence artifacts (test output, screenshots, recordings à la Cursor), risk-scored
   diffs. Early support: AI-generated PR descriptions associated with −19.3 h median review
   time (arXiv 2402.08967); Graphite's stack-aware merging; CodeRabbit Change Stack.
   Counter-evidence to respect: the Beko/Qodo study found bot comments *increased* closure
   time — summaries route attention; they don't shrink total work unless precision-filtered.
2. **A verification lane matures** so humans handle exceptions, not everything: merge
   queues for agent output, CI-as-gate, "did it pass its own checks" as the primary sort
   key. Nobody has built this yet (see Part 5.1).
3. **Ask-frequency falls under the page budget.** SRE math: ~2 pages per 12-hour shift is
   sustainable; if agents ask more than ~3 times/day/fleet, oversight decays into
   rubber-stamping (the alert-fatigue literature is directly transferable — mute rates and
   resolve rates are your oversight-decay alarms).
4. **Per-agent identity and egress control exist** so one injected agent cannot turn your
   fleet into the attacker's fleet. This is where fern's gateway becomes load-bearing.

### 1.4 Falsifiers (what would kill the thesis)

- **Diff sizes grow instead of shrink.** If agentic output keeps trending toward large
  batches (DORA: +25% AI adoption → −7.2% delivery stability, blamed on hard-to-review
  batches) and nothing forces decomposition, phone-first supervision collapses to
  notify-and-defer — useful, but not visionary. Watch: median PR size from agent tools
  year over year.
- **Hosted surfaces absorb supervision convincingly.** If Anthropic/OpenAI/Cursor mobile
  UX gets genuinely good *and* users stop caring about self-hosting (R5 evidence: they
  mostly already don't), fern's niche evaporates into a hobby. Watch: whether Amp's
  "no self-hosted deployments" stance survives enterprise pressure; whether Anthropic
  self-hosted runners generalize beyond Claude sessions.
- **opencode stalls or churns through v2.** Beta resets already happened (Jun 22 schema
  reset). A substrate that breaks quarterly caps how much superstructure is wise.
- **METR-style reversals persist.** If frontier agents remain net-negative on expert repos
  (the 19%-slower RCT), fleets just industrialize waste, and the rational equilibrium
  stays 1–3 deeply-read agents. Watch: METR follow-ups on current-generation models.

## Part 2 — microVMs vs containers: the verdict

**Decision: never-for-now. Stay Docker, convert idle-stop to freezer pause, keep a written
trigger list. Revisit quarterly.**

Why the serious players chose microVMs/gVisor — and why that reasoning doesn't transfer:

- E2B (Firecracker on Nomad+Consul), Modal (gVisor+CRIU snapshots), Fly Sprites
  (Firecracker), Cloudflare Containers, Vercel Sandbox (Firecracker), Google agent-substrate
  (gVisor checkpoint/restore or cloud-hypervisor) are all **multi-tenant platforms running
  adversarial, untrusted customer code at density economics** ($/agent-hour is their
  product). Isolation tier and restore speed *are* their moats — UFFD handlers, prefetch
  traces, diff snapshots, memory dedup are literally what they built businesses on.
- fern is **single-owner, trusted-code, own-hardware**. Its threat model (documented in
  `docs/SECURITY.md`) treats repository code as trusted-inside-the-boundary. The freezer
  cgroup gives sub-millisecond thaw + daemon overhead (~10–50 ms end-to-end expected),
  preserves in-memory state and open sockets, and requires zero re-platforming. The
  independent benchmark niche (single-host freezer-pause wake vs the LogRocket managed-cloud
  numbers: E2B 662 ms, Daytona 1254 ms, Modal 2347 ms) is open and fern's lifecycle harness
  already emits `wake-timings.tsv`.
- Honest cost of pivoting to Firecracker now: rebuild rootfs/kernel/networking/jailer;
  abandon bind mounts, named volumes, the digest-pinned `gh` image, and the entire existing
  test estate. Realistic: 10–16 weekends to reach *worse-than-today* functionality;
  indefinite to reach E2B-class restore. Opportunity cost: that is the entire Grab-prep
  build budget, spent to duplicate `kubernetes-sigs/agent-sandbox` examples or
  agent-substrate — both of which shipped while this idea sat in the backlog.

**Middle paths, ranked by trigger:**

| Trigger condition (be honest about whether it fired) | First response | Effort |
| --- | --- | --- |
| Running genuinely **untrusted third-party code** (public demo where strangers' agents execute; publishing fern as a service) | gVisor `runsc` as drop-in Docker runtime | Low (days) — accept IO/syscall penalties |
| **RAM wall**: paused-RSS × fleet exceeds host memory and you need true hibernation | Podman CRIU checkpoint/restore with `--tcp-established` (Docker's own checkpoint remains broken, containerd #12141) | Medium (1–2 wk) — watch TTY/seccomp caveats; SSE connections are the fragile case |
| Needing sub-second forks of **memory state** (Morph-Infinibranch-style parallel exploration from live state) | Filesystem-level fork (git worktrees + CoW overlay) covers the actual use case; true memory forks stay out of scope | Low |
| Becoming a **multi-tenant product** with real users | Firecracker — or more likely, don't become one (Part 8) | Months; don't |

Cost of the decision either way: staying costs ~one weekend (the freezer conversion, which
three prior documents already agreed on) and a quarterly calendar reminder. Pivoting costs
the year's build budget for isolation properties fern's threat model doesn't need.

## Part 3 — What opencode v2 makes possible (and what it blocks)

Verified against the v2 beta line fern pins (`0.0.0-next-17444`, digest-checked) and the v2
docs/spec as of Aug 23, 2026. Beta caveat applies throughout: "Method names, inputs, and
outputs may change before the stable release."

### 3.1 Already supported (build on these)

| Surface | Phone-fleet use |
| --- | --- |
| `POST /api/session/{id}/prompt` — durable admission receipt, idempotent by caller-chosen message ID, `resume`, `delivery: steer\|queue` | The dispatch primitive. fern already exploits it (exact-once delivery). Duplicate submit returns the same receipt — safe retries over cellular |
| Inbox routes (`GET .../inbox`, steer/queue/cancel per item) | Native *per-session input* inbox: prove what's pending, cancel undelivered work. Note scope: mechanical input queuing, not a semantic cross-agent task list — fern's task store is that layer |
| SQLite/WAL storage (`opencode.db`) externally inspectable | Read-only completion polling fallback; volume-level migration (below) |
| `GET /api/experimental/session/{id}/log?after=&follow=true`, finite `GET .../history` | Durable event replay with sequence cursors — the root-blocker unlock (Part 6, stage 2). Marked experimental; verify per pin |
| Caller-selected session/message IDs accepted and durable (proven by fern's contract harness) | Idempotency across restarts and migrations |
| `projectID` = git root-commit hash | Clones compute identical project IDs across machines — session continuity across workspaces nearly free |
| `POST /api/session/{id}/move` (v2) | Session relocation between directories/workspaces on one backend |
| PTY/worktree endpoints; MCP client runtime routes; skills API | Terminal access from phone UI; agent-callable infra later |
| `serve` / `attach` / official web UI at server root | fern's whole client strategy stands on this |

### 3.2 Blocked or missing (design around)

| Gap | Status (Aug 2026) | Design consequence |
| --- | --- | --- |
| Auth beyond Basic (`OPENCODE_SERVER_PASSWORD`) | Bearer staled (#24874); no OIDC; v2 OpenAPI declares no auth schemes | Survivable: fern terminates auth at its own listeners; opencode stays loopback-behind-proxy. OIDC belongs at fern's gateway layer anyway |
| Durable completion proof | `/wait` stubbed (503) everywhere; SSE volatile by contract, no Last-Event-ID; #38458 open | Poll adapter now (message/history/status/db read-only); contribute replay/wait upstream later |
| Permissions/forms durability across process restart | Process-epoch scoped on pinned profile (characterized, not assumed) | Fern fails closed — correct; approvals live in fern's store, not opencode's |
| Cross-machine session migration via export/import | Broken trio staled unfixed (#15797/#20117/#21941) | Don't build `/remote` on it. fern owns the volume: quiesce → copy `opencode.db` + git state → start elsewhere. Cleaner than export/import and entirely fern-owned |
| Sharing | v1 only; **no v2 share endpoints** | Public share URLs out of scope for v2-only fern |
| Official v2 container image | None during beta | Keep fern's digest-pinned image (already better than upstream's v1 offering for this purpose) |

**Summary:** v2 already supports the dispatch/inbox/idempotency/storage skeleton of the
phone-fleet vision; completion-proofing needs a polling adapter plus eventual upstream
contribution; notifications, approvals, trust, billing, and fleet routing are entirely
fern-owned state — which is where all differentiation lives anyway.

## Part 5 — What nobody has built yet (novel primitives, with mechanisms)

Ranked by (thesis value × buildability × Grab spillover).

### 5.1 The outcome-triage merge lane
**Gap:** No tool sorts pending agent output by *did it pass its own verification* and gates
integration accordingly (amux's `done≠verified` flag is the only germ; Graphite argues
stacking matters for AI diffs but ships no agent-output lane).
**Mechanism:** fern already has sealed immutable results, a fenced verification coordinator,
and a journaled publication phase. Add a `merge_lane` table: ordered entries referencing
sealed results, state machine `queued → verifying → ready | conflicted | rejected`, entry
only advances when the previous one merged (trunk-stability serialization). On base-SHA
drift → `conflicted` → automatically admit a *new attempt* on the same task with rebase
instructions (exact-once delivery machinery reused; no new delivery semantics). The phone
digest renders the lane, not raw events.
**Grab spillover:** this is admission control, capacity gating, and ordered effect journals
— gateway vocabulary in disguise.

### 5.2 Trust budgets enforced at the model boundary
**Gap:** Spend is displayed (amux, Factory credits) but never *enforced as policy*; earned
autonomy exists in standards drafts and Coder's firewall but is composed nowhere with a
phone-side supervisor.
**Mechanism:** fern's gateway meters tokens/\$ per attempt (usage from provider responses
cross-checked against opencode.db). Each task class carries an envelope: spend cap, tool
allowlist (injected into opencode agent config at session create), egress domains (enforced
at the gateway), max diff size. Events fern already journals update a per-workspace trust
score (verification passes ↑, force-push/out-of-scope/OOM ↓; decay on age, per the IETF PT
draft). Crossing a boundary contracts the envelope and raises a Tier-1 page with inline
raise-cap/pause actions.
**Grab spillover:** per-principal scoped credentials, tiered capacity isolation, quota
enforcement — the JD, almost verbatim.

### 5.3 Escalate-to-desk (state-carrying review deferral)
**Gap:** Every mobile client today hands off with "remember what you were doing." Nothing
carries in-progress review state between surfaces (research finding: universal gap).
**Mechanism:** When a diff exceeds the phone budget (configurable lines/risk score), Ack =
**Defer**, not Approve. fern freezes a review bundle: sealed result ID, manifest stats,
verification evidence, risk notes, draft comments captured from the phone UI, and a
deep-link (`tailscale serve` URL to `opencode attach --session …`). Opening the bundle at
a desk restores full context in one action. Requires nothing upstream.
**Thesis value:** this single primitive reconciles the phone ceiling (~50-line diffs) with
fleet-scale review debt — it converts the thesis's weakest link into a designed handoff.

### 5.4 Signed durable wake/dispatch endpoints
**Gap:** Amp proved event-driven wakes but the URL *is* the credential (their own warning);
nobody self-hosted offers signed, scoped, expiring external triggers with exactly-once
admission.
**Mechanism:** HMAC-signed URLs bound to (workspace, capability, expiry, source); replay
protection via fern's existing idempotency receipts (a duplicated webhook redelivers → same
receipt → no second task). Sources: git push, CI failure, cron, Slack/ntfy round-trip.
Store-then-ack (HTTP 202) semantics copied from Amp; delivery becomes effectively
exactly-once downstream because admission is idempotent — a genuine improvement over the
hosted incumbent, on the user's own infra.

### 5.5 The attention/cost governor
**Gap:** No tool manages the two scarce resources (review hours, budget) as first-class
constraints on concurrency.
**Mechanism:** Priority is assigned per task at admission (fern already snapshots actor +
intent transactionally). The governor enforces: running-attempts ≤ review capacity (learned
from your own triage latency); fleet spend ≤ rolling budget; violations pause the
lowest-priority attempt (quiesce fence exists) rather than paging you. Dashboard shows the
page-budget meter ("2 of 3 Tier-1 slots used today") — operationalizing the SRE Workbook
heuristic. Cheap: all inputs are state fern already computes.

## Part 7 — Traps (visionary-sounding, months-long, solo-dev-lethal)

1. **Building a native mobile app.** The sharpest personal trap on this list: React Native
   is a home-field skill and it would burn 2–3 months rebuilding what a PWA + ntfy banner
   actions already do (Tactic Remote's telemetry — 62% of approvals handled inline on the
   banner — is the proof the browser path suffices). The embedded task UI stays a PWA.
2. **The microVM pivot.** Settled in Part 2. Re-litigating it is itself the trap.
3. **Kubernetes controllers.** Fourth confirmation: GKE Agent Sandbox is GA and free;
   agent-substrate commoditized the wake-density pattern. Building this now competes with
   hyperscalers giving it away.
4. **Bidirectional live session migration.** Upstream transfer paths are broken and
   staled; Codex owns the SSH-handoff story; fern's durable tasks answer the same need
   with better semantics. Dead.
5. **Multi-harness universality.** t3code occupies "manage every harness" with 20k★ and
   full-time maintainers. fern's guarantees (exact-once, sealing, verification) are
   opencode-specific and defensible; a universal connector is neither.
6. **Review automation.** CodeRabbit/Greptile/Ellipsis/Qodo are venture-funded and
   imperfect; consuming their summaries (or a single self-hosted scorer) is fine; competing
   is a company-sized hole.
7. **Voice/ASR engineering.** Use Wispr-class keyboards, Telegram voice notes, ntfy
   replies. Zero ASR code.
8. **Multi-node scheduling before one host shines.** The 3-box Tailscale scheduler remains
   a Stage-"only-if-story-needed" item; the fleet vision works at single-host scale for a
   long time (paused-RSS × 10 ≈ manageable; governor enforces the ceiling).
9. **The meta-trap, stated plainly:** this is the fifth document agreeing the fast wake
   path is step one. It is still `ContainerStop`. The failure mode of this project has
   never been wrong strategy; it is strategy documents substituting for weekends. Cap
   future planning at one page until stages 1–4 exist.

## Part 8 — Market reality check

Is there a product here? **No — and that was settled again this month.** Terragon Labs shut
down Feb 9, 2026; Ona joined OpenAI Jun 11; gitpod self-hosted archived; Vibe Kanban
community-maintained post-Bloop; Daytona closed-source; Crystal→Nimbalyst hunting a model.
Hyperscalers give the substrate away now (GKE Agent Sandbox free tier; Cloudflare GA).
Anthropic entered self-hosted runners — for Claude sessions only, which is simultaneously
competition and proof the category is real.

Is there a *niche*? Yes, narrow and probably durable: **self-hosted, BYO-compute,
opencode-native, guarantee-bearing (exact-once/sealed/audited), phone-first supervision.**
Nobody holds it — t3code has no guarantees, Coder is enterprise, Anthropic is
single-harness, amux/Nimbalyst lack durable semantics. But the niche's TAM is power users
and its natural monetization is nil. Verdict, plainly: **portfolio artifact with genuine
daily-use personal value, possibly a small OSS audience — not a company.** Optimize it for
the Grab offer and for your own fleet; treat any user growth as upside, never as plan.

## Part 9 — Where we stand (the case against, taken seriously)

**What comes out against this project:**

1. **Opportunity cost is the real adversary.** Weekends are finite and the interview loop
   gates the actual goal. Every weekend on fern is one not on DSA/system-design. The plan
   above is sized so the Grab-critical subset (stages 1–5) fits in ~10 weekends; anything
   beyond that must justify itself against LeetCode, and mostly won't.
2. **The thesis's weakest link is measured, not speculative.** Phone review ceilings
   (~50-line diffs), METR's perception-gap data, and DORA's stability degradation all say
   review bandwidth binds first. Mitigation is design (small units, verification lane,
   escalate-to-desk), not optimism. If mitigation fails, the residual product —
   dispatch + notify + tiny approvals — is still useful but no longer visionary, and the
   essay's ambition should shrink accordingly.
3. **Platform risk compounds.** opencode v2 is beta with proven churn; every hosted vendor
   is absorbing pieces of this vision monthly; Amp could drop "no self-hosted" at any
   quarter. The moat is narrow: guarantees + self-hosted + opencode-native. It holds for
   portfolio purposes regardless — which is the only purpose that matters here.
4. **The over-design pattern is live.** Four documents of convergent strategy; a repo of
   exceptional machinery (trigger-enforced state machines, tamper-rejection tests) around
   still-missing visible wins; the single highest-consensus item unbuilt after months.
   Nothing in this document fixes that. Only sequencing does.
5. **Bus factor of one, substrate dependency, zero economic sink** — fine for a portfolio
   piece; disqualifying for anything resembling a company (Part 8).

**What comes out for it:** a working, physically-proven phone-supervised agent deployment
that almost nobody on earth has; architecture that Google and Solo.io independently
converged on; engineering rigor rare enough in OSS to anchor six interview rounds; a
verified, in-country target JD whose requirements fern can meet clause-by-clause within ten
weekends; and a five-year direction that the strongest available evidence supports as
triage-shaped and phone-delivered.

**Net:** the vision survives contact with the evidence — narrowed from "steer fleets from a
phone" to "**triage fleets from a phone; verify by infrastructure; defer depth by design**."
The project's standing is: right ideas, exceptional machinery, chronically unbuilt
headline. Execute stages 1–5 before writing or believing another word of strategy,
including this document's.
